⚙️ cManage

Componente principale per la gestione completa di operazioni CRUD (Create, Read, Update, Delete)

📖 Descrizione

cManage è il componente principale della libreria cupparis-primevue per la gestione completa di operazioni CRUD. Permette di gestire liste, inserimenti, modifiche e visualizzazioni di record in modo integrato e configurabile.

Il componente gestisce automaticamente il routing, la navigazione tra le viste e lo stato dell'applicazione, semplificando notevolmente lo sviluppo di interfacce amministrative.

🚀 Utilizzo Base

<template> <c-manage :conf="manageConf"></c-manage> </template> <script> import cupparisPrimevue from 'cupparis-primevue'; const cManage = cupparisPrimevue.cManage; export default { components: { cManage }, data() { return { manageConf: { modelName: 'ModelUser', title: 'Gestione Utenti', list: { type: 'v-list', fields: ['id', 'name', 'email'], actions: ['action-edit', 'action-view'] }, edit: { type: 'v-edit', fields: ['name', 'email', 'password'], actions: ['action-save', 'action-back'] } } } } } </script>

🧪 Esempi Realistici (da src/help/manageConfs.js)

Gestione base senza hash

Un esempio minimal già pronto per essere passato a c-manage.

import manageConfs from '@help/manageConfs' export default { data() { return { manageConf: manageConfs.semplice() // copia di ModelUser con autoUpdateHash disabilitato } } }

Lista filtrata con constraint runtime

Chiede all'utente un valore e imposta constraint e route dedicata prima di iniziare.

manageConfs.constraint().then(conf => { // conf.list.constraintKey = 'created_by' // conf.list.constraintValue = valore inserito da inputDialog // conf.list.routeName = 'list-constraint' this.manageConf = conf })

Componenti personalizzati per edit/insert/list

Mostra come sostituire i componenti di default con varianti custom.

const conf = manageConfs.m4(); // aggiunge azioni custom alla lista: // - action-custom1 apre una v-edit custom e poi torna alla lista // - action-custom2 apre un componente custom con pulsante "back" conf.listComponentName = 'list-user'; conf.editComponentName = 'insert-edit-user'; conf.insertComponentName = 'insert-edit-user';

Trovi altre varianti (m2, m3) nello stesso file per collegare componenti custom o disabilitare l'aggiornamento hash.

⚙️ Configurazione

Proprietà Obbligatorie

  • modelName Obbligatorio: Nome del modello da gestire (es. 'ModelUser')
  • list Obbligatorio: Configurazione della vista lista (tipo 'v-list')
  • edit Obbligatorio: Configurazione della vista modifica (tipo 'v-edit')

Proprietà Opzionali

  • title: Titolo da mostrare nella gestione
  • sectionTitle: Titolo della sezione
  • layout: Layout personalizzato
  • hideSearch: Nascondere la barra di ricerca (default: false)
  • autoUpdateHash: Aggiornare automaticamente l'URL con lo stato (default: true)
  • insert: Configurazione personalizzata per l'inserimento (default: usa edit)
  • view: Configurazione per la visualizzazione dettaglio
  • search: Configurazione per la ricerca avanzata
  • custom: Configurazione per viste personalizzate
  • baseRouteName: Nome base della route (default: 'manage')

💡 Esempi di Configurazione

Configurazione Semplice

var conf = { modelName: 'ModelUser', title: 'Gestione Utenti', list: { type: 'v-list', fields: ['id', 'name', 'email'], actions: ['action-edit', 'action-view'] }, edit: { type: 'v-edit', fields: ['name', 'email', 'password'], actions: ['action-save', 'action-back'] } }

Configurazione Avanzata con Viste Personalizzate

var conf = { modelName: 'ModelUser', title: 'Gestione Utenti', autoUpdateHash: true, hideSearch: false, list: { type: 'v-list', fields: ['id', 'name', 'email', 'created_at'], actions: ['action-edit', 'action-view', 'action-delete'], pagination: { pageSize: 20 } }, edit: { type: 'v-edit', fields: ['name', 'email', 'password', 'role'], fieldsConfig: { password: { type: 'w-input', inputType: 'password' }, role: { type: 'w-select', options: ['admin', 'user', 'guest'] } }, actions: ['action-save', 'action-back'] }, insert: { type: 'v-insert', fields: ['name', 'email', 'password'], actions: ['action-save', 'action-back'] }, view: { type: 'v-view', fields: ['id', 'name', 'email', 'created_at', 'updated_at'], actions: ['action-edit', 'action-back'] }, search: { type: 'v-search', fields: ['name', 'email'], actions: ['action-search', 'action-reset'] } }

👁️ Viste Disponibili

v-list

Vista lista con tabella dati. Mostra una tabella con i record del modello.

v-edit

Vista modifica record esistente. Form per modificare un record identificato da una chiave primaria.

v-insert

Vista inserimento nuovo record. Form per creare un nuovo record.

v-view

Vista sola lettura per visualizzare i dettagli di un record.

v-search

Vista ricerca avanzata. Form per filtrare i dati della lista.

custom

Vista personalizzata per casi d'uso specifici.

🎯 Azioni Predefinite

  • action-edit: Modifica record (nella lista)
  • action-view: Visualizza dettaglio record
  • action-insert: Inserisci nuovo record
  • action-save: Salva modifiche
  • action-back: Torna indietro
  • action-delete: Elimina record

🔧 Metodi Principali

  • showList(): Mostra la vista lista
  • showCustom(context): Mostra una vista personalizzata
  • updateHash(confName, type, context): Aggiorna l'URL con lo stato corrente
  • getViewList(): Ottiene il riferimento alla vista lista
  • getViewSearch(): Ottiene il riferimento alla vista ricerca
  • getViewRecord(): Ottiene il riferimento alla vista record

🛣️ Gestione Hash e Routing

Quando autoUpdateHash è true, cManage aggiorna automaticamente l'URL con lo stato corrente:

  • /manage/ModelUser/list - Vista lista
  • /manage/ModelUser/edit/123 - Modifica record con ID 123
  • /manage/ModelUser/insert - Inserimento nuovo record
  • /manage/ModelUser/view/123 - Visualizza record con ID 123
  • /manage/ModelUser/custom - Vista personalizzata

⚙️ Configurazione Componenti Personalizzati

È possibile personalizzare i componenti utilizzati:

  • editComponentName: Nome componente per edit (default: 'v-edit')
  • listComponentName: Nome componente per lista (default: 'v-list')
  • searchComponentName: Nome componente per ricerca (default: 'v-search')
  • insertComponentName: Nome componente per insert (default: 'v-insert')
  • viewComponentName: Nome componente per view (default: 'v-view')
  • customComponentName: Nome componente personalizzato

Esempio con Componenti Personalizzati

var conf = { modelName: 'ModelUser', editComponentName: 'insert-edit-user', insertComponentName: 'insert-edit-user', listComponentName: 'list-user', // ... altre configurazioni }

📝 Note

  • cManage estende CrudComponent e fornisce tutte le funzionalità base
  • Le configurazioni delle viste vengono normalizzate automaticamente
  • Le azioni vengono automaticamente collegate all'istanza di manage
  • Supporta constraint per filtrare i dati in base a parametri
  • Gestione automatica dello stato e della navigazione
  • Integrazione completa con il sistema di routing Vue Router
