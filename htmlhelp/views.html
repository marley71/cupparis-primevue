👁️ Views

Componenti per la visualizzazione e gestione di dati

📖 Descrizione

Le Views sono componenti per la visualizzazione e gestione di dati. Ogni view rappresenta un diverso modo di presentare e interagire con i dati del modello.

Tutte le views estendono vBase che fornisce funzionalità comuni come gestione route, caricamento dati, gestione widget e azioni, e lifecycle hooks.

🚀 Utilizzo Base

<template> <c-view :conf="viewConf"></c-view> </template> <script> export default { data() { return { viewConf: { type: 'v-list', modelName: 'ModelUser', fields: ['id', 'name', 'email'], actions: ['action-edit', 'action-view'] } } } } </script>

👁️ Tipi di View Disponibili

v-list

Vista lista con tabella dati. Mostra una tabella con i record del modello.

  • fields: Campi da mostrare nella tabella
  • actions: Azioni disponibili per ogni riga
  • pagination: Configurazione paginazione
  • sorting: Configurazione ordinamento
  • filtering: Configurazione filtri

v-edit

Vista modifica record esistente. Form per modificare un record identificato da una chiave primaria.

  • pk: Chiave primaria del record da modificare
  • fields: Campi del form
  • actions: Azioni disponibili (es. 'action-save', 'action-back')

v-insert

Vista inserimento nuovo record. Form per creare un nuovo record.

  • fields: Campi del form
  • actions: Azioni disponibili (es. 'action-save', 'action-back')

v-view

Vista sola lettura per visualizzare i dettagli di un record.

  • pk: Chiave primaria del record da visualizzare
  • fields: Campi da mostrare
  • actions: Azioni disponibili (es. 'action-edit', 'action-back')

v-search

Vista ricerca avanzata. Form per filtrare i dati della lista.

  • fields: Campi di ricerca
  • actions: Azioni disponibili (es. 'action-search', 'action-reset')
  • updateHash: Aggiorna l'URL con i parametri di ricerca

v-list-edit

Vista lista con modifica inline. Permette di modificare i record direttamente nella tabella.

v-list-hasmany

Vista lista per relazioni hasMany. Mostra i record correlati in una sottolista.

v-record

Vista record singolo. Visualizza un singolo record con tutti i suoi dettagli.

⚙️ Proprietà Comuni a Tutte le Views

  • type: Tipo di view (es. 'v-list', 'v-edit')
  • modelName: Nome del modello
  • routeName: Nome della route per le chiamate API
  • fields: Array di nomi campi o configurazioni campi
  • fieldsConfig: Configurazione dettagliata dei campi/widget
  • actions: Array di azioni disponibili
  • actionsConfig: Configurazione dettagliata delle azioni
  • constraintKey: Chiave per filtrare i dati
  • constraintValue: Valore del filtro

💡 Esempi di Configurazione

Configurazione Lista

var listConf = { type: 'v-list', modelName: 'ModelUser', routeName: 'users_list', fields: ['id', 'name', 'email', 'created_at'], actions: ['action-edit', 'action-view', 'action-delete'], pagination: { pageSize: 20 } }

Configurazione Edit

var editConf = { type: 'v-edit', modelName: 'ModelUser', routeName: 'users_update', pk: 123, fields: ['name', 'email', 'password'], fieldsConfig: { password: { type: 'w-input', inputType: 'password' } }, actions: ['action-save', 'action-back'] }

Configurazione Insert

var insertConf = { type: 'v-insert', modelName: 'ModelUser', routeName: 'users_create', fields: ['name', 'email', 'password'], fieldsConfig: { password: { type: 'w-input', inputType: 'password', required: true } }, actions: ['action-save', 'action-back'] }

Configurazione Search

var searchConf = { type: 'v-search', modelName: 'ModelUser', fields: ['name', 'email'], fieldsConfig: { name: { type: 'w-input', label: 'Nome' }, email: { type: 'w-input', label: 'Email' } }, actions: ['action-search', 'action-reset'], updateHash: true }

🔧 View Base (vBase)

Tutte le views estendono vBase che fornisce funzionalità comuni:

  • Gestione route e chiamate API
  • Caricamento dati (load, reload)
  • Gestione widget e campi
  • Gestione azioni
  • Callbacks lifecycle (beforeLoad, afterLoad, beforeDraw, afterDraw)

🔧 Metodi Principali delle Views

  • load(): Carica i dati dal server
  • reload(): Ricarica i dati
  • draw(): Renderizza la view
  • getViewData(): Ottiene i dati del form/view
  • getWidget(name): Ottiene un widget per nome
  • getAction(name): Ottiene un'azione per nome
  • setParams(params): Imposta parametri per la lista
  • instance(): Restituisce l'istanza della view

🔄 Lifecycle Hooks

Le views supportano diversi hook del ciclo di vita:

  • beforeLoad: Chiamato prima del caricamento dati
  • afterLoad: Chiamato dopo il caricamento dati
  • beforeDraw: Chiamato prima del rendering
  • afterDraw: Chiamato dopo il rendering
  • beforeSetRouteValues: Chiamato prima di impostare i valori della route
  • afterSetRouteValues: Chiamato dopo aver impostato i valori della route

Esempio Lifecycle Hooks

var viewConf = { type: 'v-list', modelName: 'ModelUser', beforeLoad() { console.log('Prima del caricamento'); // Modificare parametri, aggiungere filtri, etc. }, afterLoad(data) { console.log('Dati caricati:', data); // Elaborare dati, aggiornare UI, etc. }, beforeDraw() { console.log('Prima del rendering'); }, afterDraw() { console.log('Dopo il rendering'); } }

🛣️ Gestione Route

Le views utilizzano il sistema Route per le chiamate API:

  • Creazione automatica della route basata su routeName
  • Gestione parametri (pk, constraint, filtri)
  • Supporto per GET e POST
  • Gestione errori e risposte

🔍 Constraint e Filtri

Le views supportano constraint per filtrare i dati:

var listConf = { type: 'v-list', modelName: 'ModelUser', constraintKey: 'user_id', constraintValue: 123, // Mostra solo i record con user_id = 123 }

📝 Note

  • Tutte le views estendono CrudComponent
  • I metodi possono essere sovrascritti tramite configurazione
  • Supportano caricamento asincrono dei dati
  • Integrazione completa con il sistema di routing
  • Supportano template dinamici e rendering condizionale
  • Gestione automatica degli errori e messaggi
  • Supporto per paginazione, ordinamento e filtri
